## Context
You are given access to the following ontology definitions. Each ontology definition is in turtle syntax and delimited by <ontology></ontology> tags.
- td: describes the ThingDescription ontology which defines Web-of-Things devices as having property, action and even affordances
- hmas: describes the Hypermedia MAS ontology which defines conceptual items such as HypermediaPlatforms that contain Workspaces and Artifacts (that can also be TD Things) with which agents can interact
- hctl and json-schema: describe vocabularies for hypermedia control and JSON schema descriptions
- homeont: defines a small vocabulary for smarthomes, detailing the notions of home, rooms and a list of smart devices and the command types that can be possibly invoked on the devices

## Task
Write a SPARQL query that can be executed against such an RDF graph whose purpose is to retrieve the devices and their specific affordances that are required to satisfy the user request. Make sure that affordances are bound to their correct devices.

If you identify multiple commands in the user request, write a SPARQL query for every individual command in turn.
Each SPARQL query must retrieve specifically:
  - "workspace": the URI of the workspace containing the artifact,
  - "artifact": the URI of the artifact whose representation contains required affordances, 
  - "affordance_name": the name of the action affordance to be invoked,
  - "target_uri": the target URI to be invoked described in the appropriate affordance, 
  - "parameter_name": the name of a parameter that needs to be part of the payload for the affordance invocation.

Keep in mind that some affordances may not require any input parameters, in which case "parameter_name" need not be bound.

Each SPARQL query must have the relevant namespace prefixes included and formatted properly as IRIREFs.

## Output Format
The output follows the JSON structure below:
{
    "queries": [
        {
            "command": "<text corresponding to an individual command>",
            "query": "<SPARQL_QUERY for the command>"
        }
    ]
}

The number of entries in the "queries" array corresponds to the number of individual commands identified in the user request.
Each SPARQL query contains only its required syntax, no other comments are included.
